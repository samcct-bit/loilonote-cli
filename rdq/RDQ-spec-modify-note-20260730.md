# RDQ 需求規格：擴充筆記修改功能

## 一句話任務
在 Loilonote MCP Server 中新增「修改筆記」的 API 端點，支援將外部或 AI 生成的教材批次處理後安全寫回系統。

## ✅ 已確認
- 擴充方向：修改筆記，把外部教材或 AI 產生的內容自動寫回 Loilonote 筆記（Ⅲ）
- 安全防護：AI 可自行執行修改，但需預先實作自動備份與復原機制（Ⅲ）
- 基礎架構：延用現有的 CDP Token 機制與 JSON-RPC 通訊協議（Ⅰ）

## ❓ 假設（未確認，已採預設值，隨時可推翻）
- 筆記格式處理 → 預設沿用現有解析出的 JSON frames 格式進行重新打包
- API 限制 → 預設每次批次上傳前會停頓 1-2 秒，以避免踩到 Rate Limit
- 使用對象 → 預設此功能主要供本地掛載的 AI Agent 單人使用，不考量多帳號併發情境

## ➕ 已採納（象限Ⅳ）
- 納入「批次處理機制」：先全部載回本地算完再打包上傳，避免頻繁打 API 被伺服器封鎖

## ❌ 排除項（明確不做）
- 暫不實作 `--dry-run` 模式（透過本地批次機制與自動備份作為安全網）
- 暫不實作建立新繳交箱或自動批改作業功能

## 📋 一段式需求規格
開發者希望在現有 `@samcct-bit/loilonote-mcp` 專案中擴充**修改筆記**的功能，允許 AI Agent 將產生的內容寫回。考量到官方 API 限制，資料流需採用**批次處理機制**：AI 會在本地端將所有內容運算完畢並重新打包後，再一次性上傳覆蓋，而非逐筆打 API 修改。在進行任何破壞性寫入前，系統必須強制執行**自動備份機制**以確保資料可復原。此功能主要提供給本地 AI 助理（如 Cursor/Claude）呼叫。

## ✔ 驗收條件
- [ ] 能成功透過 MCP 覆寫/新增內容至指定的筆記 ID
- [ ] 寫入前系統會自動在本地（或雲端）備份原始筆記的 ZIP 檔
- [ ] 內容處理在本地運算完成後，才進行一次性的上傳動作
